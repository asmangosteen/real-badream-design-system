# Page Control

> Figma 파일: [바드림 Design System](https://www.figma.com/design/2OcDq1pJgavJMLHvsdpf8S/%EB%B0%94%EB%93%9C%EB%A6%BC-Design-System?node-id=2039-2150) — 진열 프레임 `2039:2150` ("Page Control")
> 기계 판독용 값은 [`page-control.json`](./page-control.json)을 함께 참고합니다. 이 문서와 page-control.json은 항상 같은 소스에서 나온 값이어야 합니다.

## 0. 문서 범위와 샘플링 방법

Page Control은 **Type(On Light/On Dark) × Dots(2/3/4/5/6/7/8+) × Selection(1~Dots) 3축, 70-변형 컴포넌트**입니다. Dots당 Selection 값이 1~Dots로 달라지는 비직교(non-orthogonal) 축이라, Type 1종당 2+3+4+5+6+7+8=35개, ×2 Type=**70개**로 계산됩니다(`get_metadata`로 전수 확인).

- 변형 수가 많아 축별 전략적 샘플링을 했습니다 — **9개 노드**를 `get_design_context`로 실측했습니다:
  1. **베이스라인**(Dots=2, Selection=1, On Light): `2039:2151`
  2. **중간 선택 예시**(Dots=3, Selection=2, On Light·On Dark 각 1개): `2039:2185`, `2039:2192` — 양쪽 Type의 색상 차이 확인용
  3. **Dots=8+ 오버플로우 패턴**(On Light, Selection 1/2/4/7/8 총 5개): `2039:2761`, `2039:2795`, `2039:2863`, `2039:2965`, `2039:2999` — Selection 위치에 따른 "축소 도트" 규칙을 파악하기 위한 표본
  4. **Dots=8+ 오버플로우, On Dark 대조**(Selection=4): `2039:2880` — Light에서 확인한 축소 규칙이 Dark에도 동일하게 적용되는지 대조
- 각 노드의 실제 도트 색상은 `get_design_context`가 반환하는 `<img>` 에셋(SVG)의 URL만으로는 확인할 수 없어, **에셋 SVG 원본을 직접 fetch해 `fill`/`fill-opacity`/`r`(반지름) 값을 실측**했습니다(2·3장 근거).
- `get_variable_defs`는 진열 프레임 전체(`2039:2150`)에 1회 호출했습니다.
- `get_motion_context`를 진열 프레임 전체(`2039:2150`, recursive=true)에 호출해 빈 결과(`{"nodes":[]}`)를 확인했습니다.
- 절대 추측으로 토큰명을 만들지 않았습니다. 저장소 `tokens/*.json`에 없는 값은 "확인 필요" 또는 "기존 토큰에 없음"으로 명시합니다.

## 1. 컴포넌트 개요

Page Control은 캐러셀/온보딩 등에서 **현재 페이지 위치를 원형 도트(dot)로 표시하는 인디케이터**입니다. State(Hover/Pressed/Disabled) 축이 전혀 없는 순수 표시용(non-interactive) 컴포넌트입니다.

| 축(Axis) | 값 | 의미 |
|---|---|---|
| **Type** | On Light / On Dark | 배경 밝기에 따른 도트 색상 팔레트. 밝은 배경(On Light)엔 어두운 톤, 어두운 배경(On Dark)엔 밝은 톤 도트를 사용 |
| **Dots** | 2 / 3 / 4 / 5 / 6 / 7 / 8+ | 전체 페이지(도트) 개수. `8+`는 9개 이상의 페이지를 8개 도트 안에 압축 표현하는 특수 모드(3장) |
| **Selection** | 1 ~ Dots | 현재 선택(활성)된 페이지 위치. Dots 값에 따라 1~Dots 범위로 제한됨(비직교 축) |

## 2. 레이아웃·색상 스펙 (Dots=2/3 표본 기준)

- **컨테이너**: `flex` row, `items-center justify-center`, 도트 간 gap `spacing/spacing-06`=8px, 컨테이너 사방 padding `spacing/spacing-06`=8px. (변수명이 다른 컴포넌트의 `spacing/06`과 달리 `spacing/spacing-06`으로 되어 있으나 값 8px은 동일 — 4장 참고)
- **도트 크기**: 8×8px 원(`circle r=4`), 축소 없는 일반 상태 기준 반지름 `r=4`(8장 참고)
- **색상**(SVG `fill`/`fill-opacity` 직접 실측, 4개 상태 전수):

| Type | 상태 | fill | opacity | 비고 |
|---|---|---|---|---|
| **On Light** | 미선택 | `#03091A`(`color/gray/900-*` 계열) | 20% | `color/gray/900-20` |
| **On Light** | 선택 | `#454C58` | 100% | `neutral/700` |
| **On Dark** | 미선택 | `#FDFDFD`(`color/gray/50-*` 계열) | 20% | `color/gray/50-20` |
| **On Dark** | 선택 | `#F6F7F7` | 100% | `neutral/100` |

**패턴**: 선택된 도트는 항상 해당 Type의 강조 뉴트럴 톤(On Light=`neutral/700` 진한 회색, On Dark=`neutral/100` 밝은 회색)으로 100% 불투명하게, 미선택 도트는 반대 극단의 뉴트럴(On Light=검정 계열, On Dark=흰색 계열)을 20% 불투명도로만 씁니다 — 배경과 정반대 톤을 옅게 깔아 미선택 도트를 은은하게 표현하는 방식입니다.

## 3. Dots=8+ 오버플로우("축소 도트") 패턴 — 5개 Selection 표본 실측

Dots=8+는 8개 도트 슬롯 안에 9페이지 이상을 표현하기 위해, **선택 위치에서 먼 쪽 끝의 도트 1~2개를 반지름을 줄여("축소") 시각적으로 사라지는 느낌**을 줍니다. 색상(`fill`/`opacity`)은 변하지 않고 **반지름(`r`)만 4→3→2로 단계적으로 작아집니다**.

| Selection | 반지름 패턴(도트1→도트8) | 관찰 |
|---|---|---|
| **1** | `4,4,4,4,4,4,3,2` | 우측 끝 2개(7·8번)만 축소, 좌측은 전부 정상(4) |
| **2** | `4,4,4,4,4,4,3,2`(도트1 재확인, 우측 축소 동일) | Selection=1과 동일 패턴 |
| **4** | `4,4,4,4,4,4,3,2` | 선택이 중앙에 가까워도 우측 축소 패턴 유지 |
| **7** | `2,3,4,4,4,4,4,4` | **좌측 끝 2개(1·2번)로 축소가 이동** — Selection=1~4와 반대 방향 |
| **8** | `2,3,4,4,4,4,4,4` | Selection=7과 동일 패턴(좌측 축소 유지) |

**핵심 발견**: 축소는 "선택 위치에서 가장 먼 2개 도트"에 걸리는 것이 아니라(그랬다면 Selection=4에서는 좌우 모두 후보), **정해진 한쪽 끝(우측 7·8번 또는 좌측 1·2번)에서만** 발생하며, Selection이 앞쪽 절반(1~4, 확인된 범위)일 때는 우측이, 뒤쪽 끝(7~8)일 때는 좌측이 축소됩니다. 이는 "8개 도트짜리 윈도우가 선택 위치를 따라 슬라이드하다가, 선택이 윈도우 끝에 닿으면 반대쪽으로 축소 표시가 넘어가는" 전형적인 캐러셀 인디케이터 패턴으로 보입니다. **다만 전환이 정확히 Selection=5/6 중 어느 지점에서 일어나는지는 이번 5개 표본(1·2·4·7·8)에 포함되지 않아 확인 필요**입니다.

Dark 테마(On Dark, Selection=4, `2039:2880`)에서도 동일한 구조(도트7·8이 별도 축소 에셋)가 확인되어, **이 축소 규칙은 Type과 무관하게 동일하게 적용**되는 것으로 보입니다.

## 4. 토큰 변수명 불일치

이 컴포넌트의 spacing 변수는 `spacing/spacing-06`(값 8px)로, 저장소 내 다른 대부분의 컴포넌트가 쓰는 `spacing/06` 네이밍과 형식이 다릅니다. 값 자체는 `ref-spacing-06`(8px)과 정확히 일치하나, Figma 변수 이름 자체가 이중으로 접두된("spacing/" 안에 다시 "spacing-06") 것으로 보아 이 컴포넌트가 다른 시점/다른 방식으로 변수를 바인딩했을 가능성이 있습니다 — 기능상 문제는 없으나 Figma 파일 정리 시 참고할 만한 사항입니다.

## 5. 인터랙션(모션) 스펙

**모션 데이터 없음.**

`get_motion_context`를 진열 프레임 전체(`2039:2150`, recursive=true)에 호출했으나 `{"nodes":[]}`인 빈 결과를 반환했습니다. 페이지 전환 시 도트가 선택 상태를 바꾸는 트랜지션(색상 전환, 8+ 모드의 축소/확장 애니메이션)에 대한 duration/easing 값이 Figma 파일에 정의되어 있지 않습니다.

## 6. 접근성

- Page Control은 일반적으로 장식적 요소(실제 슬라이드 콘텐츠에 이미 포커스 가능한 대체 수단이 있는 캐러셀의 경우)이거나, 도트 자체가 클릭 가능한 페이지 이동 버튼(`role="tablist"`+`role="tab"` 또는 `aria-label="N번째 페이지로 이동"`)일 수 있는데, Figma 파일에는 이 중 어떤 상호작용 모델을 의도했는지 규정이 없습니다 — 확인 필요.
- 현재 선택된 도트를 스크린리더가 인지할 수 있도록 `aria-current="true"` 또는 `aria-selected="true"` 연결이 필요해 보이나 확인 필요.
- Dots=8+ 모드에서 "몇 번째/총 몇 페이지"라는 정보가 시각적 축소로만 표현되고 텍스트로 노출되지 않아, 스크린리더 사용자는 전체 페이지 수·현재 위치를 알 수 없습니다 — `aria-label="8페이지 중 4번째"` 같은 보완이 필요해 보이나 확인 필요.
- 미선택 도트(20% 불투명도)와 선택 도트(100%)의 명암 차이가 WCAG 명암비 기준을 만족하는지 수치 검증은 이번 조사에서 수행하지 않았습니다.

## 7. 토큰 매칭 요약

**정확히 일치**
- On Light 미선택: `#03091A` 20% → `color/gray/900-20`(저장소 alpha 팔레트와 일치)
- On Light 선택: `#454C58` → `neutral/700`(`sys-color-neutral-700`)
- On Dark 미선택: `#FDFDFD` 20% → `color/gray/50-20`
- On Dark 선택: `#F6F7F7` → `neutral/100`(`sys-color-neutral-100`)
- 도트 크기 8×8px, 도트 간 gap·컨테이너 padding 8px → `ref-spacing-06`

**기존 토큰에 없음**
- Dots=8+ 모드의 반지름 축소 단계(4→3→2px)와 그 트리거 규칙(어느 쪽 끝이 축소되는지) 자체를 규정하는 토큰/문서는 저장소에 없음(개별 반지름 값 자체는 임의 토큰이 아니라 Figma 도형 속성)
- Type(On Light/On Dark)별 도트 색상 매핑 규칙을 명시하는 "Page Control 전용" 시맨틱 토큰은 저장소에 없음(개별 색상 값 자체는 토큰과 일치)

**확인 필요**
- `spacing/spacing-06` 변수명 이중 접두 원인(4장)
- Dots=8+ 축소 방향이 정확히 Selection=5 또는 6 중 어디서 전환되는지(3장)
- 도트가 실제로 클릭 가능한 네비게이션 요소인지, 순수 장식 표시인지(6장)
- 접근성 마크업(`aria-current`, `role="tablist"`, 전체 페이지 수 텍스트 대체) 연결 규정
- WCAG 명암비 수치 검증

| Dots=8+ 축소 패턴(On Light) | Selection=1 `2039:2761` · Selection=2 `2039:2795` · Selection=4 `2039:2863` · Selection=7 `2039:2965` · Selection=8 `2039:2999` |
