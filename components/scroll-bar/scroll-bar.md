## 1. 컴포넌트 개요

스크롤 가능한 영역의 현재 위치를 보여주는 **순수 표시용 인디케이터**입니다.

**Figma 컴포넌트 설명 원문**(디자이너가 직접 작성):

> Absolute Position 상태로 다른 컴포넌트에 Overlay 해서 사용됩니다.
> 스크롤을 하면 노출되며, 멈춰있는 상태일 경우 노출하지 않습니다.
> Vertical, Horizontal 각 Type의 높이와 너비는 컴포넌트의 규격에 비례합니다.
> 노출 위치는 Vertical은 컴포넌트의 우측 끝에서 8px 떨어진 곳, Horizontal은 하단 끝에서 8px 떨어진 곳입니다.

> **⚠️ 위 인용은 문서화 시점의 Figma 원문입니다.** 마지막 문장의 여백은 **2026-09-18에 `8px` → `2px`으로 바뀌었습니다**("다시 보니 8px 은 너무 크다"). **디자이너가 Figma도 갱신 완료**했으므로 지금은 Figma·구현·이 문서가 모두 2px입니다(4장).

| 축(Axis) | 값 | 기본값 | 의미 |
|---|---|---|---|
| **Type** | Vertical / Horizontal | Vertical | 스크롤 방향. 세로 목록은 Vertical, 가로 캐러셀은 Horizontal |
| **Position** | Top / Middle / Bottom | Top | **스크롤 진행률 예시**(0% / 50% / 100%). 3단계 상태가 아닙니다 — 3장 참고 |

**구조는 2겹뿐입니다.**

```
트랙(컴포넌트 프레임)  ← 배경 없음(투명). 스크롤 가능한 전체 길이를 나타냄
└─ thumb(Rectangle)   ← 유일하게 보이는 요소. 현재 위치와 보이는 분량을 나타냄
```

## 2. 치수 · 색상 스펙

### 2-1. 트랙 (컴포넌트 프레임)

| 항목 | Vertical | Horizontal | 토큰 매칭 |
|---|---|---|---|
| Figma 실측 크기 | 6 × 180px | 180 × 6px | — |
| **두께** | 6px (너비) | 6px (높이) | 기존 토큰에 없음(고정 치수) |
| **길이** | 180px | 180px | **고정값 아님** — 아래 참고 |
| radius | `radius/12` = 999px | `radius/12` = 999px | `ref-radius-12` — **정확히 일치** |
| 배경 | **없음**(`fills` 빈 배열) | **없음** | — |

- **길이 180px은 진열용 값입니다.** 컴포넌트 설명대로 감싸는 컴포넌트의 규격에 비례합니다. 실사용 인스턴스에서 실제로 184 / 178 / 174px로 제각각입니다(6장).
- **트랙에 배경이 없습니다.** 레일이 보이지 않고 thumb만 떠 있습니다 — iOS 스타일 오버레이 스크롤바입니다. radius 999는 실제로 보이지 않지만 값 자체는 설정되어 있습니다.

### 2-2. thumb

| 항목 | Vertical | Horizontal | 토큰 매칭 |
|---|---|---|---|
| **두께** | 6px (너비) | 6px (높이) | 트랙 두께와 **동일** — 가로축을 꽉 채웁니다 |
| Figma 실측 길이 | 60px (높이) | 60px (너비) | **고정값 아님** — 2-3 참고 |
| radius | `radius/12` = 999px | `radius/12` = 999px | `ref-radius-12` — **정확히 일치** |
| 색 | `color/gray/900-40` `#03091a` 40% | 동일 | `ref-color-gray-900-40` — **정확히 일치** |

두 Type의 색·두께·radius가 **완전히 동일**합니다. 방향만 다릅니다.

### 2-3. ⚠️ thumb 길이는 콘텐츠 비율로 계산합니다 (2026-09-18 디자이너 확정)

Figma의 60px은 **트랙 180px 기준 "3페이지 분량" 예시값**입니다. 고정 규격이 아닙니다.

```
thumb 길이 = max(24px, 트랙 길이 × (보이는 영역 ÷ 전체 콘텐츠))
```

- **최소 길이 24px** — 두께 6px의 4배입니다. 목록이 아주 길면 비율 계산값이 두께와 비슷해져 막대가 아니라 동그라미로 보이므로 하한을 둡니다.
  (예: 트랙 174px에서 20페이지 분량이면 비율 계산값이 8.7px이라 24px로 고정됩니다. 트랙 174px 기준 콘텐츠가 약 7.25페이지를 넘으면 하한이 걸립니다.)
- 하한이 걸린 뒤에도 **끝까지 도달해야 합니다** — 이동 거리를 그만큼 줄여서 Position=100%일 때 트랙 아래(오른쪽) 끝에 닿게 합니다.
- **⚠️ 이 규칙과 24px 하한은 Figma에 없습니다.** 2026-09-18 디자이너 지시가 출처입니다.

## 3. Position 축 — 실제 동작 모델

### 3-1. ⚠️ Figma의 세 변형은 "상태"가 아니라 "예시 스냅샷"입니다 (2026-09-18 디자이너 확정)

실제 스크롤바는 **연속적으로** 움직입니다. Figma의 Top/Middle/Bottom은 진행률 0% / 50% / 100% 지점을 진열해 둔 것입니다.

| Position | 스크롤 진행률 | thumb 위치 |
|---|---|---|
| **Top** | 0% (맨 처음) | 트랙 **시작 끝**에 정렬 |
| **Middle** | 50% (중간) | 트랙 **가운데**에 정렬 |
| **Bottom** | 100% (맨 끝) | 트랙 **끝 끝**에 정렬 |

**⚠️ Figma의 thumb y/x 좌표(0 · 60 · 120)를 규격으로 옮기지 마세요.** 트랙 180px · thumb 60px 조합에서만 맞아떨어지는 예시값입니다. 트랙이나 thumb 길이가 달라지면 어긋납니다(실사용 인스턴스에서 실제로 어긋나 있으며, 디자이너 확인 결과 **예시로 만든 것이라 문제가 아닙니다**). 구현은 좌표가 아니라 **진행률**로 계산합니다.

```
thumb 위치 = (트랙 길이 − thumb 길이) × 스크롤 진행률(0~1)
```

Position=Bottom(진행률 1)이면 이 식이 자동으로 트랙 끝에 붙습니다.

### 3-2. Horizontal에서 Top/Bottom은 좌/우를 뜻합니다

축 이름이 세로 기준이라 가로 타입에서는 반대로 읽힐 수 있습니다. **Figma 변형 이름을 그대로 유지**하되(2026-09-18 디자이너 결정) 뜻은 아래 표가 정본입니다.

| Position | Vertical | Horizontal |
|---|---|---|
| `Top` | 위쪽 끝 | **왼쪽 끝** |
| `Middle` | 가운데 | 가운데 |
| `Bottom` | 아래쪽 끝 | **오른쪽 끝** |

## 4. 배치 규칙

**`position: absolute`로 스크롤 영역 위에 겹쳐 놓습니다.** 레이아웃 흐름에 끼어들지 않으므로 콘텐츠를 밀어내지 않습니다.

### 4-0. ⚠️ 스크롤 컨테이너 **안**에 넣으면 안 됩니다

가장 틀리기 쉬운 지점입니다. **`position: absolute`는 흐름에서만 빠질 뿐 스크롤에서는 못 빠집니다.** 스크롤 컨테이너의 자식으로 두면 콘텐츠와 함께 밀려 올라가 화면 밖으로 사라집니다 — 아래로 642px 스크롤하면 스크롤바도 642px 위로 올라갑니다.

**스크롤하지 않는 래퍼**를 하나 두고, 스크롤은 안쪽 요소가 맡으며, 스크롤바는 **래퍼의 자식(= 스크롤 영역의 형제)** 으로 둡니다.

```html
<!-- 래퍼는 스크롤하지 않습니다 -->
<div style="position: relative">
  <div class="bd-scroll-area" style="overflow: auto">…콘텐츠…</div>
  <ScrollBar visible={…} progress={…} ratio={…} />
</div>
```

> 저장소 스토리북도 처음에 이 실수를 했습니다. 스크롤바가 트랙 기준으로는 정상 위치인데
> 둘이 함께 밀려나 화면에서 사라지는 증상이라, **트랙 대비 좌표만 재면 정상으로 보입니다.**
> 검증할 때는 반드시 **래퍼(스크롤하지 않는 기준)** 대비 좌표로 재세요.

| Type | 고정되는 변 | 여백 |
|---|---|---|
| Vertical | 컨테이너 **우측** 끝 | **2px** (`ref-spacing-02`) |
| Horizontal | 컨테이너 **하단** 끝 | **2px** (`ref-spacing-02`) |

**2px은 2026-09-18에 8px에서 줄인 값입니다** (*"다시 보니 8px 은 너무 크다"*). 초판·초기 인스턴스는 8~10px이었지만 **디자이너가 Figma도 2px으로 갱신 완료**했습니다(2026-09-18). 지금은 Figma와 저장소가 일치합니다. 구현은 `--bd-scrollbar-offset` 기본값이 곧 이 값입니다.

### 4-1. OS 기본 스크롤바를 반드시 꺼야 합니다

커스텀 오버레이 스크롤바를 쓰면서 네이티브 스크롤바를 그대로 두면 **두 개가 동시에 보입니다.** 스크롤 컨테이너에서 네이티브 막대만 감추고 스크롤 기능은 그대로 둡니다.

```css
.bd-scroll-area { scrollbar-width: none; -ms-overflow-style: none; }
.bd-scroll-area::-webkit-scrollbar { display: none; }
```

- 저장소 구현은 `ScrollBar.css`에 `.bd-scroll-area` 보조 클래스로 들어 있습니다.
- **⚠️ 데스크톱에서는 마우스로 끌 수 있는 막대가 사라집니다.** 이 컴포넌트가 드래그를 받지 않으므로(7장) **모바일 전용 영역에만 쓰세요.** 휠·키보드(방향키·PageUp/Down) 스크롤은 영향받지 않습니다.

### 4-2. 나머지 두 변의 여백

**⚠️ 나머지 두 변의 여백은 Scroll Bar가 정하지 않습니다** (2026-09-18 디자이너 결정).
Vertical의 위·아래, Horizontal의 좌·우 여백은 **감싸는 컴포넌트가 자기 내부 여백에 맞춰 정합니다.** 그래서 실사용 인스턴스마다 0px · 11px · 13px로 다릅니다(6장) — 이는 불일치가 아니라 의도된 자유도입니다. 트랙 길이도 그 여백을 뺀 값이 됩니다.

구현에서는 이 값을 `--bd-scrollbar-inset` CSS 변수(기본 0)로 엽니다.

### 4-3. 둥근 모서리 회피 — thumb을 radius만큼 밀어냅니다 (2026-09-18 디자이너 지시)

컨테이너에 `border-radius`가 있으면 thumb이 **양 끝에서 둥근 모서리에 물려 잘립니다.** thumb은 고정 변에서 2px 안쪽에 있는데, 모서리의 곡선 구간(모서리에서 radius 이내)에서는 그 위치가 아직 컨테이너 바깥이라 잘려 나갑니다.

**해결: 양 끝을 컨테이너 radius만큼 추가로 밀어**, thumb이 곡선 구간에는 아예 들어가지 않게 합니다.

- radius 구간(모서리에서 radius 이내)에는 thumb이 들어가지 않으므로 잘림이 완전히 사라집니다.
- 트랙의 실질 길이 = 컨테이너 길이 − (`inset` + `radius`) × 2. thumb 이동 범위도 그만큼 줄지만, 진행률 1에서는 여전히 (밀린) 끝에 정확히 닿습니다.
- 구현은 `--bd-scrollbar-radius` CSS 변수(기본 0)로 열고, 스토리북 컴포넌트는 `radius` prop으로 받습니다. **컨테이너의 `border-radius` 값을 그대로 넘기면 됩니다.**
- 양 끝(main-axis)만 밀립니다. 고정 변(2px)은 그대로입니다.

**⚠️ 이 규칙은 Figma에 없습니다** — 2026-09-18 디자이너 지시가 출처입니다. 사각(radius 없는) 컨테이너에서는 넘길 필요가 없습니다(기본 0).

## 5. 인터랙션(모션) 스펙

**Figma 프로토타입 반응 0건** — 컴포넌트 셋에도 6개 변형 어디에도 반응이 없습니다.

> `get_motion_context`가 빈 결과라는 이유로 "모션 없음"을 결론짓지 않았습니다. Plugin API로 `node.reactions`를 전수 확인한 결과가 0건입니다(`components/README.md` 모션 규칙 참고).

컴포넌트 설명에 **"스크롤을 하면 노출되며, 멈춰있는 상태일 경우 노출하지 않습니다"** 라고만 있고 시간 값이 없어, 아래 값을 지시로 확정했습니다.

| 구간 | 값 |
|---|---|
| **등장** | 즉시(`0ms`) — 스크롤이 시작되는 순간 바로 보입니다 |
| **머무름** | 스크롤이 멈춘 뒤 **`1000ms` 대기** |
| **사라짐** | **`300ms` 페이드아웃**(`opacity` 1 → 0) |

- **⚠️ 이 세 값은 Figma에 없습니다.** iOS 기본 스크롤 인디케이터 관례값이며 2026-09-18 디자이너 지시가 출처입니다. 재실측 때 "Figma에 근거가 없다"는 이유로 지우지 마세요.
- 저장소 표준 인터랙션(Hover 150ms · Pressed 50ms · Figma Slow)과는 **별개**입니다. 저건 상태 전환용이고 이건 자동 노출/숨김입니다.
- 대기 시간이 다시 초기화되는 조건(스크롤 재개 시 타이머 리셋)은 일반적인 구현 관례를 따릅니다.
- `prefers-reduced-motion`에서는 페이드 없이 즉시 사라지게 합니다(저장소 공통 규칙, `docs/INTERACTION.md`).

## 6. 실사용 현황 (인스턴스 18개 전수)

파일 전체를 훑어 이 컴포넌트의 인스턴스를 전부 찾았습니다. **모두 `❖ Select` 페이지의 Select 컴포넌트 안**에 있고, **전부 `Type=Vertical`** 입니다.

| 쓰인 곳 | 트랙 높이 | 컨테이너 높이 | 위/아래 여백 | 우측 여백 |
|---|---|---|---|---|
| `Frame 8` | 184 | 184 | 0 / 0 | 8 |
| Select `Size=S` | 178 | 200 | 11 / 11 | 10 |
| Select `Size=M` · `Size=L` | 174 | 200 | 13 / 13 | 9 |

- **트랙 길이가 셋 다 다릅니다** — "컴포넌트 규격에 비례한다"는 설명이 실제로 지켜지고 있습니다.
- 전부 `layoutPositioning: ABSOLUTE`입니다 — 설명의 "Absolute Position 상태로 Overlay"와 일치합니다.
- 우측 여백이 8 / 9 / 10px로 조금씩 다릅니다. **이 표는 2026-09-18 여백 변경 이전에 실측한 Figma 현황**이며, 새 규칙은 **2px**입니다(4장). 이후 디자이너가 Figma를 2px으로 갱신 완료했습니다.
- **`Type=Horizontal` 실사용 사례는 파일 안에 아직 없습니다.** 스펙만 정의된 상태입니다.

## 7. 접근성

- **⚠️ 순수 표시 전용입니다** (2026-09-18 디자이너 확정). 사용자가 thumb을 잡아끌 수 없습니다.
  - `pointer-events: none`으로 클릭·드래그를 받지 않게 하고, 밑에 깔린 콘텐츠의 터치를 가로채지 않게 합니다.
  - `aria-hidden="true"`로 스크린리더에서 감춥니다. 스크롤 위치는 네이티브 스크롤 컨테이너가 이미 알려 주므로 중복 안내가 됩니다.
  - Figma에 State 축(Hover/Pressed)이 없는 것과도 일치합니다. Avatar·Divider와 같은 "순수 표시용 컴포넌트" 분류입니다.
  - 두께 6px은 권장 터치 영역 44px에 한참 못 미치는데, **드래그를 받지 않으므로 문제가 되지 않습니다.**
- **자동으로 사라지는 것 자체가 접근성 고려 대상입니다.** 스크롤 위치 정보가 시각적으로만, 그것도 일시적으로만 제공됩니다. 다만 네이티브 스크롤 컨테이너를 쓰면 보조기술은 별도 경로로 위치를 얻으므로 실질적 손실은 없습니다.
- **밝은 배경 전용입니다.** thumb이 `gray/900-40`(검정 40%)이라 어두운 배경 위에서는 대비가 확보되지 않습니다.
  → **어두운 배경용 변형은 필요해지면 그때 추가**하기로 했습니다(2026-09-18 디자이너 결정). 지금은 확인 필요 항목이 아닙니다.

## Corner Smoothing (2026-09-23 추가)

바드림 디자인시스템은 모든 Radius 에 **Corner Smoothing 60%** 를 함께 씁니다(`docs/DESIGN.md` 9.2). 모서리가 완전한 원·알약이라 Corner Smoothing 이 걸려 있어도 모양이 바뀌지 않습니다. 구현을 바꾸지 않았습니다.

Figma 실측: 2026-09-23 Figma Plugin API `cornerSmoothing` 전수 조회(컴포넌트 셋 안의 모든 노드).

| 레이어 | Radius | Figma Smoothing | 구현 |
|---|---|---|---|
| Thumb | 999px (`radius/12`) | 60% | 변화 없음(알약) |
| 컴포넌트 틀 | 999px | 0% | 해당 없음 |

- 완전한 원·알약은 곡선이 들어갈 자리가 없어 smoothing 이 자동으로 0 이 됩니다(Figma·구현 공통) — 모양이 바뀌지 않으므로 구현을 바꾸지 않았습니다.
- 컨테이너 모서리 회피용 `radius` prop 은 **감싸는 컨테이너의** radius 를 받는 값이라 그대로 씁니다. 컨테이너가 squircle 이어도 thumb 이 물리지 않습니다 — squircle 은 원호보다 일찍(radius × 1.6 지점부터) 휘기 시작하지만, thumb 끝이 놓이는 자리(모서리에서 radius + 2px)에서 안쪽으로 들어온 양이 0.1~0.2px(radius 12~20 계산값)뿐이고 thumb 은 가장자리에서 2px 떨어져 있습니다.
