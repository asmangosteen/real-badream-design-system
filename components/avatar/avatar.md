# Avatar

> Figma 파일: [바드림 Design System](https://www.figma.com/design/2OcDq1pJgavJMLHvsdpf8S/%EB%B0%94%EB%93%9C%EB%A6%BC-Design-System?node-id=2262-13275) — Component Set `2262:13275` ("Avatar")
> 기계 판독용 값은 [`avatar.json`](./avatar.json)을 함께 참고합니다. 이 문서와 avatar.json은 항상 같은 소스에서 나온 값이어야 합니다.

## 0. 문서 범위와 샘플링 방법

Avatar는 **Size 축 하나만 가진 7-변형 컴포넌트 셋**입니다(`12/16/20/24/32/40/48px`). Chip 문서(3-4장)에서 이미 이 컴포넌트를 하위 서브컴포넌트로 다룬 적이 있으나(16px 버전만), 이번 문서에서는 **7개 Size 전체를 개별 실측**했습니다.

- 7개 노드 전부 `get_design_context`로 실측했습니다(`get_variable_defs`·`get_metadata`·`get_motion_context`·`get_screenshot` 각 1회 포함).
- 절대 추측으로 토큰명을 만들지 않았습니다. 저장소 `tokens/*.json`에 없는 값은 "확인 필요" 또는 "기존 토큰에 없음"으로 명시합니다.
- **State(Hover/Pressed/Disabled) 축이 없습니다** — Checkbox·Chip과 달리 Avatar 자체는 인터랙션 상태를 갖지 않는 순수 표시용(non-interactive) 컴포넌트입니다.

> **이미지 콘텐츠 관련 확인**: Figma 컴포넌트 내부 이미지는 실제 배포 시 체커보드 무늬(Figma의 "미할당 이미지" 자리표시자)로 렌더링되어 있습니다. 이는 실제 사용자 프로필 사진이 들어갈 자리를 나타내는 예시일 뿐이며, 컴포넌트 자체는 임의의 이미지를 채울 수 있는 슬롯(`<img>` 소스 교체)으로 설계되어 있습니다. 이 문서의 모든 스펙(테두리·radius·크기)은 이미지 콘텐츠와 무관하게 고정된 값입니다.

## 1. 컴포넌트 개요

Avatar는 사용자 프로필 이미지를 원형으로 표시하는 순수 표시용 컴포넌트입니다. Chip(Avatar+Text 등 Contents)에서 서브컴포넌트로 재사용되는 것 외에, 프로필·리스트·댓글 작성자 표시 등 범용적으로 쓰일 수 있는 아톰입니다.

| 축(Axis) | 값 | 의미 |
|---|---|---|
| **Size** | 12 / 16 / 20 / 24 / 32 / 40 / 48px | 아바타 원의 지름. 다른 축(State/Type/Theme)은 없음 |

## 2. Size별 스펙 (7개 전체 실측)

| Size | 노드 | 테두리 두께 | 토큰 | 테두리 색상 | Radius |
|---|---|---|---|---|---|
| **12px** | `2262:13274` | `borderwidth/01` = 0.5px | `ref-borderwidth-01` | `color/gray/900-5` = `rgba(3,9,26,0.05)` | `radius/12` = 999px |
| **16px** | `2262:13273` | `borderwidth/02` = 1px | `ref-borderwidth-02` | 동일 | 동일 |
| **20px** | `2262:13272` | `borderwidth/02` = 1px | `ref-borderwidth-02` | 동일 | 동일 |
| **24px** | `2262:13271` | `borderwidth/02` = 1px | `ref-borderwidth-02` | 동일 | 동일 |
| **32px** | `2262:13270` | `borderwidth/02` = 1px | `ref-borderwidth-02` | 동일 | 동일 |
| **40px** | `2262:13269` | `borderwidth/02` = 1px | `ref-borderwidth-02` | 동일 | 동일 |
| **48px** | `2262:13268` | `borderwidth/02` = 1px | `ref-borderwidth-02` | 동일 | 동일 |

모든 값이 저장소 토큰(`tokens/radius.json`)과 **정확히 일치**합니다.

**핵심 규칙**: **12px에서만** 테두리가 `borderwidth/01`(0.5px)로 더 얇고, **나머지 6개 Size(16px 이상)는 전부 `borderwidth/02`(1px)로 동일**합니다. 테두리 색상(`gray-900-5%`)과 radius(999px, 완전한 원)는 Size와 무관하게 전 사이즈 공통입니다.

## 3. 이미지 처리 규칙

- 이미지는 `object-cover`로 채워져 원형 프레임(`overflow-clip` + `radius/12`)에 잘려 표시됩니다 — 원본 비율과 무관하게 항상 정사각형으로 크롭되어 원 안에 꽉 차게 표시됩니다.
- `<img>` 태그가 컨테이너의 `inset-0 size-full`로 배치되어, 실제 구현 시 다양한 실사용 이미지(사용자 프로필 사진 등)를 그대로 소스 교체하면 됩니다.
- 대체 텍스트(`alt`)는 Figma 코드 출력상 빈 문자열로 되어 있어, 실제 구현 시 접근성을 위해 별도로 채워야 합니다(7장 참고).

## 4. 인터랙션(모션) 스펙

**모션 데이터 없음.**

`get_motion_context`를 컴포넌트 셋 전체(`2262:13275`, recursive=true)에 호출했으나 빈 결과(`{"nodes":[]}`)를 반환했습니다. Avatar에는 State 축 자체가 없으므로(0장 참고), 이는 "확인 필요"가 아니라 애초에 인터랙션이 정의될 이유가 없는 순수 표시용 컴포넌트임을 뒷받침합니다.

## 5. Chip과의 관계

`components/chip/chip.md` 4장에서 Avatar가 Chip의 "Avatar + Text" 등 Contents 조합에 서브컴포넌트로 쓰이는 것을 확인했으며, 이때는 항상 **16px 버전만** 사용되었습니다. 이번 문서에서 실측한 16px 스펙(테두리 1px, `gray-900-5%`)은 Chip 문서의 값과 **정확히 일치**합니다(상호 검증됨).

## 6. 접근성

- **대체 텍스트 필수**: Avatar는 의미를 전달하는 이미지(사용자 식별)이므로, 실제 구현 시 `alt`에 사용자 이름 등 식별 가능한 텍스트를 채워야 합니다. Figma 파일 자체에는 이 규정이 명시되어 있지 않습니다 — 확인 필요.
- **이미지 로드 실패 시 대체 표시**: 이 컴포넌트 셋에는 이니셜(글자) 폴백이나 기본 아이콘 폴백 변형이 존재하지 않습니다. 실제 서비스에서 이미지가 없거나 로드에 실패하는 경우의 폴백 UI(이니셜, 기본 아이콘 등)는 Figma 파일에 별도로 정의되어 있지 않으므로 확인 필요합니다.
- **최소 크기**: 12px는 매우 작아 단독으로는 클릭 가능한 요소로 쓰기 어렵습니다(Chip 안에서 장식적으로만 쓰이는 크기로 보임). 실제 프로필 링크 등 클릭 가능한 아바타로 쓸 경우 44px 권장 터치 영역 확보가 필요합니다.

## 7. 토큰 매칭 요약

**정확히 일치**
- 전 Size 공통 Radius 999px → `ref-radius-12`
- 12px 테두리 0.5px → `ref-borderwidth-01`
- 16~48px(6종) 테두리 1px → `ref-borderwidth-02`
- 테두리 색상 `gray-900-5%` → `ref-color-alpha-gray-900-5`

**기존 토큰에 없음**
- Size 스케일 자체(12/16/20/24/32/40/48px)는 저장소에 별도의 "Avatar 크기" 토큰으로 존재하지 않는 고정값입니다. 앞부분(12/16/20/24)은 `assets/icons/`의 아이콘 사이즈 스케일과 겹치지만, 32/40/48px는 아이콘 스케일에 없는 Avatar 전용 확장 크기입니다.

**확인 필요**
- 이미지 로드 실패 시 폴백 UI(이니셜/기본 아이콘) 정의 여부
- `alt` 텍스트 규정
- 12px처럼 매우 작은 사이즈가 클릭 가능한 요소로 쓰일 때의 최소 터치 영역 확장 규정
