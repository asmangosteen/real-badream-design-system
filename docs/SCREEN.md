# 바드림 앱 - 화면 흐름 및 패턴 가이드 (통합)

> 이 문서는 바드림 앱의 두 핵심 플로우 화면 기준서를 하나로 합친 것입니다.
> - Part 1. 착한구독(구독): 전기이륜차 구독 및 운영 라이프사이클
> - Part 2. 신차구매(바이패스): 전기이륜차 신차구매 및 보조금 신청
> 두 문서 모두 원본 내용을 손실 없이 보존했습니다. 각 Part는 독립적으로 읽을 수 있습니다.

# Part 1. 착한구독 (구독)

# 바드림 앱 착한구독 화면 정리

> 목적: `착한구독 화면.zip`에 포함된 바드림 앱의 **착한구독 / 전기이륜차 구독 / 렌탈·리스 운영** 화면을 이미지 없이 텍스트 기준서로 정리한다.  
> 사용 방식: 다른 AI, 디자이너, 개발자가 원본 이미지를 보지 않아도 IA, 플로우, 반복 UI 패턴, 화면별 핵심 키워드를 이해할 수 있도록 한다.  
> 원칙: 이미지는 포함하지 않는다. 섹션별 대표 화면은 **파일 경로 인덱스**로만 기록한다.

## 1. 폴더 순서 기반 IA 및 전체 플로우

### 1.1 착한구독 메인 구매/신청 플로우

```text
0. 홈-내차고
  ├─ 내 차고가 비어있거나 구독 진행 건이 있는 상태 확인
  ├─ 홈 카드에서 착한구독 진입
  └─ 진행 중인 구독 건은 상태별 CTA로 재진입
      ↓
1. 상품리스트
  ├─ 상단 탭: 신차구독 / 중고구독 HOT / 단기구독
  ├─ 필터칩: 전체 / BSS형 / 홈충전형 / 승계 등
  ├─ 상품 카드: 이미지, 구독타입, 모델명, 배지, 월·주 구독료, 일 환산 금액
  └─ 상품 선택
      ↓
2. 상품상세
  ├─ 상품 이미지, 모델명, 구독료, 일 환산 금액, 공유/문의
  ├─ 바드림 단독 혜택, 바드림케어, BSS/홈충전, 상품구성, 바이크 정보 확인
  ├─ 안내 바텀시트: 구독타입 / 바드림케어 / 바로출고
  └─ 구독료 조회하기 CTA
      ↓
3. 옵션선택
  ├─ 연령 선택
  ├─ 바이크 타입: 홈충전형 / BSS형
  ├─ 구독 타입: 인수상품 / 반납상품
  ├─ 계약기간, 보험종류, 색상, 배터리 추가, 기타 옵션 선택
  └─ 선택완료
      ↓
4. 구독료확인
  ├─ 선택 옵션 내역 확인 및 펼침
  ├─ 월 납부 / 주 납부 선택
  ├─ 일 환산 금액 안내
  ├─ 착한 마일리지 적립 혜택 확인
  └─ 신청하고 마일리지 혜택받기 CTA
      ↓
5. 예약금결제
  ├─ 예약금 30,000원 결제 안내
  ├─ 결제방법 선택: 카드 / 가상계좌
  ├─ 카드 결제 또는 가상계좌 발급/입금
  └─ 예약금 결제 완료
      ↓
6. 신청정보 입력
  ├─ 신청 유형 선택: 개인 / 개인사업자 / 법인사업자
  ├─ 로그인 기반 기본정보 확인
  ├─ 상세정보, 주소, 사업자정보, 대표자/실사용자/담당자 정보 입력
  └─ 입력 완료
      ↓
7. 카드등록
  ├─ 정기결제 카드 등록
  ├─ 본인명의/타인명의 카드 검증
  ├─ 정기결제일 선택: 매주 / 매월
  └─ 등록 완료
      ↓
8. 서류제출
  ├─ 신청유형별 필수서류 확인
  ├─ 주민등록초본은 정부24 + 카카오톡 인증으로 발급
  ├─ 사업자등록증명, 운전면허증, 신분증, 법인등기부등본 등 파일 업로드
  └─ 서류 제출 완료
      ↓
9. 주요안내 ~ 전자서명
  ├─ 계약기간, BSS, 과태료, 보조금 환수, 반납상품 등 주요 안내 확인
  ├─ 끝까지 스크롤 후 확인 완료
  ├─ 구독계약서 전자서명
  └─ 구독 신청 접수 완료
      ↓
10. 구독현황
  ├─ 접수: 제출서류/계약서 확인 중
  ├─ 출고: 바이크 출고 중, 인도일 선택
  ├─ 인도: 인도완료, 인수증 서명
  ├─ 리뷰: 제품/서비스 리뷰 작성
  └─ 운영: 납부, 미납, 과태료, AS, 사고접수, BSS 안내, 서류 다운로드
      ↓
11. 리뷰쓰기
  ├─ 서비스 리뷰 작성
  ├─ 제품 리뷰 작성
  └─ 내가 쓴 리뷰 확인
```

### 1.2 상품 유형별 분기

```text
상품리스트 / 상품상세 / 옵션선택 / 구독료확인 단계에서 상품 유형이 분기됨

신차구독
  ├─ BSS형 또는 홈충전형 선택
  ├─ 인수상품 또는 반납상품 선택
  ├─ 계약기간, 보험, 색상, 배터리, 기타옵션 선택
  └─ 착한 마일리지 혜택과 예약금 결제로 연결

중고구독
  ├─ HOT 탭으로 강조
  ├─ 주행거리, 6개월 등 상품 특성이 카드에 추가 노출
  ├─ 중고 상태/조건을 상세에서 확인
  └─ 옵션 확인 후 동일한 예약금/신청정보/카드/서류 플로우로 연결

단기구독
  ├─ 1주일부터 가볍게 시작한다는 상단 배너 노출
  ├─ 1주 단위 자유롭게 신청 가능 메시지
  ├─ 예약 시 안내 바텀시트 제공
  └─ 옵션 확인 후 구독료 확인 및 신청 플로우로 연결
```

## 3. 전역 화면 패턴

### 3.1 화면 골격

- 대부분 iOS 앱 화면이며 status bar `9:41`, 상단 내비게이션, 본문, 하단 sticky CTA 구조를 사용한다.
- 상단 액션은 맥락에 따라 `뒤로가기 chevron`, `닫기 X`, 우측 `문의`로 나뉜다.
- 신청 단계 화면에는 상단에 얇은 파란색 progress bar가 노출된다.
- 배경은 흰색 또는 `#F5F5F6` 계열의 밝은 회색이며, 중요한 정보는 흰색 rounded card로 묶는다.
- 하단 CTA는 iOS safe area 위에 고정된다. 비활성은 연회색, 활성은 바드림 블루, 위험/미납은 레드로 구분한다.

키워드: `iOS mobile`, `Pretendard WOTFD`, `white UI`, `status bar`, `close X`, `back chevron`, `문의`, `top progress bar`, `bottom sticky CTA`, `safe area`, `rounded card`, `light gray background`.

### 3.2 타이포그래피와 정보 위계

- 기본 폰트는 **Pretendard WOTFD**.
- 페이지 제목은 크고 굵은 문장형으로 사용한다. 예: `구독 옵션을 선택해주세요.`, `우선, 예약금을 결제해주세요.`, `정기결제 카드를 등록해주세요.`
- 보조 설명은 회색 본문으로, 사용자가 해야 할 일과 이유를 함께 안내한다.
- 금액은 굵은 숫자와 `원` 단위를 조합한다. 예: `351,000원`, `90,000원`, `30,000원`, `380,000P`.
- 혜택/마일리지/착한구독 라벨은 보라색 또는 블루 그라데이션 계열로 별도 강조한다.
- 위험/주의/미납/과태료는 레드 계열 텍스트, 아이콘, CTA로 구분한다.

키워드: `large title`, `semantic line break`, `price emphasis`, `benefit badge`, `red warning`, `gray helper text`, `blue CTA`.

### 3.3 탭, 필터, 선택 컴포넌트

- 상품리스트 상단은 넓은 탭 구조다. 선택 탭은 진한 네이비 배경, 비선택 탭은 회색/빨간 텍스트로 표현한다.
- 필터는 pill chip으로 제공한다. 선택된 chip은 진한 배경, 비선택 chip은 흰색+border다.
- 옵션 입력에는 dropdown, radio, segmented control, checklist, bottom sheet selection이 반복된다.
- dropdown이 열리면 파란 border와 chevron up/down이 강조되고, 선택지는 흰색 리스트로 이어진다.
- radio 선택은 파란 원형 선택 상태와 회색 미선택 상태로 명확히 구분한다.

키워드: `tab navigation`, `filter chip`, `selected chip`, `dropdown open`, `radio group`, `segmented control`, `checklist`, `chevron`, `bottom sheet selection`.

### 3.4 카드와 리스트 패턴

- 상품 카드는 이미지 영역, 상품 메타, 모델명, 배지, 가격, 일 환산 금액으로 구성된다.
- 구독현황 카드는 상단에 모델 이미지/모델명/주문번호, 중간에 단계 진행바, 하단에 상세정보와 메뉴 리스트를 쌓는다.
- 홈 내 차고 카드는 접힘/펼침 상태가 있으며, 접힌 상태는 요약 중심, 펼친 상태는 CTA와 진행 단계 중심이다.
- 정보 리스트는 `좌측 라벨 - 우측 값` 형태가 많고, 상세 메뉴는 아이콘 + 텍스트 + 우측 chevron으로 구성된다.

키워드: `product card`, `garage card`, `status card`, `accordion`, `label-value list`, `icon menu row`, `chevron row`, `summary card`.

### 3.5 하단 CTA 패턴

- 단일 주요 CTA: `선택완료`, `예약금 결제하기`, `확인`, `다음`, `서명하기`, `미납 구독료 즉시 납부하기`.
- 이전/다음 분할 CTA: 좌측 outline `← 이전`, 우측 filled/disabled `다음`.
- 화면 하단에 보조 안내가 붙는 경우가 있다. 예: 예약금 결제 화면의 `내용을 확인하였으며, 이후 진행에 동의해요.`
- 위험 액션은 빨간색 full-width CTA를 사용한다. 예: 미납 납부, 과태료 확인.

키워드: `full width CTA`, `primary blue`, `disabled gray`, `danger red`, `outline previous`, `sticky bottom`, `consent text`, `safe area`.

### 3.6 바텀시트와 팝업 패턴

- 바텀시트는 결제방법 선택, 은행 선택, 관계 선택, 결제일 선택, 보험 안내, 구독타입/바드림케어 안내 등에서 반복된다.
- 바텀시트 상단에는 제목과 닫기 X가 있고, 본문에는 선택 리스트 또는 안내 카드가 배치된다.
- 팝업은 이탈/취소/방식 변경 재확인/삭제 확인처럼 되돌릴 수 있는지 확인해야 하는 상황에 쓰인다.
- 팝업 버튼은 보통 좌측 취소/보조, 우측 확인/주요 액션 구조다.

키워드: `bottom sheet`, `modal popup`, `dimmed background`, `cancel confirm`, `method selection`, `bank selection`, `relation selection`, `payment date picker`.

### 3.7 완료/대기/오류 패턴

- 완료 화면은 중앙 체크 아이콘과 큰 완료 문구, 하단 확인 CTA를 사용한다.
- 대기 화면은 처리 중인 일을 명시한다. 예: 카드 결제중, 초본 발급 화면대기중, 카카오톡 인증 대기.
- 오류는 공격적인 문구보다 `정상적으로 처리되지 않았어요`, `다시 시도` 형태로 안내한다.
- 미납/과태료/보조금 환수 가능성 등은 레드로 강하게 표시하되, 다음 행동 CTA를 함께 제공한다.

키워드: `success check`, `waiting state`, `loading`, `error popup`, `retry`, `time out`, `red state`, `next action`.

  - `신차구매` 카드: 보조금 신청까지.

### 4.12 `11. 리뷰쓰기`

#### 역할

구독 경험과 제품 경험을 리뷰로 남기는 화면이다. 서비스 리뷰와 제품 리뷰가 분리되어 있으며, 제품 리뷰는 별점/사진/상세내용이 강조된다.

#### 서비스 리뷰

- 제목: `착한구독 이용은 어떠셨는지 2가지 여쭤볼게요.`
- 질문 구조:
  - Q1: 구독 신청 과정이 편리했는지.
  - Q2: 구독 신청부터 바이크를 받기까지 느낀 점.
- 별점 또는 감정 평가.
- 텍스트 입력 영역.
- CTA: 입력 전 disabled, 입력 후 `다음` 활성.

#### 제품 리뷰

- 바이크 썸네일과 모델명.
- 질문: `바이크는 어떠셨나요?`
- 별점 선택.
- 사진 첨부:
  - 카메라 아이콘.
  - 최대 10장 카운트.
  - 선택된 사진 썸네일과 삭제 아이콘.
  - 사진선택 바텀시트: `사진 찍기`, `앨범에서 사진 선택`, `닫기`.
- 상세내용 입력:
  - 글자수 카운트.
  - 유효성 안내: `최소 20자 이상 입력해주세요.`
- 완료:
  - 작성 완료 후 확인 CTA.
- 내가 쓴 리뷰:
  - 작성한 리뷰 카드, 별점, 날짜, 제품 사진, `착한구독 이용후기` 링크/버튼.

#### 팝업

- 리뷰쓰기 취소 팝업:
  - `나중에 작성할까요?`
  - 작성 중인 리뷰는 저장되지 않음을 안내.
  - `이어서 하기` / `나가기` 액션.

#### AI 키워드

`review writing`, `service review`, `product review`, `star rating`, `photo upload`, `thumbnail strip`, `text area`, `character count`, `validation`, `cancel popup`, `my review`, `user-generated content`.

## 7. UX Writing 패턴

### 7.1 주요 문장 톤

- 기본적으로 `~해주세요`, `~해요`, `~되었어요`, `~할게요` 중심의 친근한 해요체를 사용한다.
- 사용자가 지금 해야 할 일을 제목에서 바로 말한다.
- 완료/성공은 `~되었어요`로 끝내고, 다음 행동은 버튼으로 명확히 제시한다.
- 긴 법적/계약성 안내는 상대적으로 단정하고 정확한 문장을 사용하되, 하단 CTA는 여전히 앱다운 문장으로 정리한다.

## 8. 디자인/구현 참고 키워드

### 8.1 레이아웃 토큰 관점

- 모바일 기준 좌우 margin은 약 20px로 보이며, 카드 내부 padding은 16~24px 계열을 반복한다.
- 카드 radius는 12~20px 범위의 둥근 모서리를 사용한다.
- 상단 progress bar는 2~4px 두께의 파란색 선으로 단계 진행률을 나타낸다.
- bottom sticky CTA 영역은 흰 배경/상단 border/충분한 safe area 여백으로 고정된다.
- 스크롤형 화면에서는 하단 CTA가 본문 위에 overlay되지 않도록 충분한 bottom padding이 필요하다.

### 8.2 컬러 역할

| 역할 | 컬러 성격 | 사용 예 |
|---|---|---|
| Primary | 바드림 블루 | 주요 CTA, 선택 radio, 선택 chip, 링크형 액션 |
| Secondary/Dark | 네이비/딥블루 | 상품 탭 선택 상태, 구독현황 상단 단계 진행 영역 |
| Neutral | 회색 계열 | 배경, divider, 비활성 CTA, 보조 설명 |
| Purple | 보라/라벤더 | 착한구독 마일리지, 혜택 배지, 리뷰/리워드 |
| Red | 경고/위험 | 미납, 과태료, 보조금 환수 주의, 서류보완 요청 |
| Green | 성공/포함 | BSS 이용권 포함, 제출완료, 정상 상태 보조 강조 |

### 8.3 아이콘/일러스트레이션

- 상품/홈: 바이크 이미지가 핵심 시각 자산이다.
- 상태/구독현황: 신청, 접수, 출고, 인도, 리뷰 단계 아이콘을 사용한다.
- 완료: 체크 아이콘 중심.
- 결제: 카드, 계좌, 은행 로고, KCP PG 로고.
- 서류: upload/file/document 아이콘.
- 운영: 과태료, AS, 사고접수, 마일리지, BSS 아이콘.
- 리뷰: 별점, 카메라/이미지 아이콘.

## 9. AI가 화면을 재해석할 때의 주의사항

1. **착한구독은 신차구매(바이패스)와 연결되지만 다른 영역이다.**  
   바이패스가 보조금 신청/신차구매 중심이라면, 착한구독은 전기이륜차를 구독하고 운영하는 전체 라이프사이클에 가깝다.

2. **구독료 조회 전 옵션선택이 핵심이다.**  
   연령, 바이크타입, 구독타입, 계약기간, 보험종류, 색상, 배터리, 기타옵션이 구독료 산정의 주요 입력값이다.

3. **구독료확인 화면은 가격표가 아니라 혜택 전환 화면이다.**  
   월/주 구독료뿐 아니라 착한 마일리지 적립을 크게 보여주고, `신청하고 380,000P 혜택받기`처럼 혜택을 CTA에 직접 연결한다.

4. **예약금은 신청 확정의 첫 결제다.**  
   예약금 30,000원 결제 후 구독 접수, 잔여금 결제, 바이크 수령으로 이어진다.

5. **정기결제 카드 등록은 구독 운영 리스크와 직접 연결된다.**  
   카드 등록, 결제일 선택, 타인명의 카드의 가족관계 제한, 현대카드 등록 불가 같은 정책 문구가 중요하다.

6. **서류제출은 신청유형별 동적 화면이다.**  
   개인, 개인사업자, 법인사업자에 따라 필수서류와 명의 안내가 달라진다. 단순 업로드 화면이 아니라 정부24/카카오 인증형 발급 플로우를 포함한다.

7. **구독현황은 단순 주문조회가 아니다.**  
   접수/출고/인도/리뷰뿐 아니라 납부, 미납, 과태료, AS, 사고접수, BSS 안내, 인수증, 서류 다운로드까지 관리하는 운영 허브다.

8. **상태별 CTA 컬러가 매우 중요하다.**  
   정상 진행은 블루, 비활성은 회색, 미납/과태료/보완 필요 같은 긴급 상태는 레드를 사용한다.

9. **문구는 고객 옆에서 도와주는 톤으로 유지한다.**  
   `~해주세요`, `~해요`, `~되었어요`, `~할게요`를 기본으로 하되, 법적 고지는 정확하게 작성한다.

## 3. 전역 화면 패턴

### 3.1 화면 골격

- 흰색 또는 아주 밝은 회색 배경 위에 정보 카드를 쌓는 모바일 앱 구조.
- 대부분의 핵심 화면은 iOS status bar `9:41`, 상단 `뒤로가기` 또는 `닫기 X`, 우측 `문의` 텍스트를 가진다.
- 다음 행동은 거의 항상 하단 sticky CTA에 위치한다.
- 복잡한 화면은 회색 divider 또는 큰 여백으로 섹션을 분리한다.
- 긴 안내/서류 화면은 스크롤 캡처이며, 상단에 현재 단계, 중간에 안내/폼/리스트, 하단에 CTA가 반복된다.

키워드: `iOS mobile`, `white UI`, `status bar`, `back chevron`, `close X`, `문의`, `bottom sticky CTA`, `section divider`, `rounded card`, `scroll page`.

### 3.2 타이포그래피

- 기본 폰트: **Pretendard WOTFD**.
- 제목은 Bold 또는 SemiBold 성격의 굵은 Pretendard로 짧고 직접적인 문장 사용.
- 본문은 회색 계열, 줄바꿈은 의미 단위로 나뉨.
- 금액은 가장 강한 위계로 표시한다. 예: `1,600,000원`, `30,000원`, `1,163,000원`.
- 할인율, 차감 금액, 오류 문구는 빨간색과 함께 강조한다.
- 완료/성공은 체크 아이콘과 `완료`, `제출완료`, `결제완료` 같은 명확한 상태 문구로 표현한다.

키워드: `Pretendard WOTFD`, `bold title`, `large price`, `gray helper text`, `red discount`, `red validation`, `green/blue check`, `direct CTA label`.

### 3.3 컬러와 상태

- Primary Blue: 주요 버튼, 선택 상태, 진행 상태, 링크, step active에 사용.
- Deep Navy / Dark Gray: 제목, 가격, 핵심 정보, 주문상세 헤더에 사용.
- Light Blue: 선택된 카드, 출고예정일 카드, 보조금 정보, 안내 pill 배경에 사용.
- Mint / Green: 보조금 확인, 신청 지자체, 제출완료/성공 상태 일부에 사용.
- Red: 할인율, 오류, 보완필요, 신청불가, 금액 초과, destructive 경고에 사용.
- Gray: 비활성, placeholder, helper text, divider, empty state, 완료 전 예정 step에 사용.

키워드: `primary blue`, `deep navy`, `light blue selected state`, `mint subsidy`, `red error`, `gray disabled`, `neutral card background`.

### 3.4 정보 배치 원칙

- 커머스형 정보는 `상품 이미지 → 제조사/모델명 → 가격 → 배지/칩 → CTA` 순서.
- 행정형 정보는 `현재 해야 할 일 → 왜 필요한지 → 준비물/조건 → 제출/확인 CTA` 순서.
- 결제형 정보는 `결제할 금액 → 나중에 낼 금액 → 결제수단 → 주의사항 → 결제 CTA` 순서.
- 상태형 정보는 `현재 상태 제목 → 예상 일정/결과 → 타임라인 → 사용자 액션` 순서.

키워드: `summary first`, `what to do now`, `why this matters`, `price transparency`, `timeline`, `CTA at bottom`.

## 4. 반복 컴포넌트 패턴

### P01. Header / Navigation

- 기본 구조: `뒤로가기 chevron` + 중앙 또는 좌측 제목 + 우측 `문의`.
- 닫기가 필요한 플로우는 `X`를 사용한다. 서류작성, 전자서명, 결제 중 이탈 확인에서 반복된다.
- 홈은 로고, 알림 bell, 메뉴 아이콘이 함께 있고, `내 차고` 카드로 이어진다.
- 주문상세는 일반 흰색 헤더가 아니라 진한 네이비 상단 블록을 사용해 주문번호와 모델 정보를 강조한다.

키워드: `app header`, `back`, `close`, `contact`, `notification`, `hamburger`, `order detail navy header`.

### P02. Bottom Sticky CTA

- 주요 액션은 화면 하단 fixed/sticky 영역에 배치된다.
- Primary CTA는 파란색 filled button, 흰색 텍스트, 큰 radius.
- Secondary CTA는 흰 배경 + outline 또는 연한 회색/연한 파란 배경.
- Disabled CTA는 연회색 버튼 + 회색 텍스트. 주변 안내문으로 왜 비활성인지 설명한다.
- 제품상세는 `문의하기` 작은 버튼 + 큰 `MY 최저가로 구매하기` 버튼 조합이 반복된다.

대표 문구: `MY 최저가로 구매하기`, `보조금 신청하기`, `다음`, `완료`, `예약금 30,000원 결제하기`, `서류 제출하기`, `서명하기`, `잔여금 결제하기`, `알림 받으면 돌아올게요`.

### P03. Stepper / Progress / Timeline

- 주문확인~예약금결제~서류제출은 3단계 stepper를 사용한다.
- 현재 단계는 파란 원과 숫자, 완료 단계는 check, 예정 단계는 회색 원으로 표현한다.
- 서류작성의 깊은 단계는 상단 얇은 progress bar가 상태를 대신한다.
- 주문현황은 세로 timeline을 사용한다. 단계명, 날짜, 상태 pill이 세로로 쌓인다.
- 홈 내 차고 카드는 축약된 상태 카드 안에서 진행 상태를 요약한다.

키워드: `3-step checkout`, `progress bar`, `vertical timeline`, `completed check`, `active step`, `pending step`, `status pill`.

### P04. Card / Accordion

- 상품, 주문, 옵션, 보조금, 결제내역, 서류, 진행상태 모두 rounded card 구조를 사용한다.
- 접기/펼치기가 있는 카드에는 chevron up/down이 붙는다.
- 펼침 상태에서는 필수옵션, 선택옵션, 수량 stepper, 변경하기 버튼 등 상세 정보가 나타난다.
- 접힘 상태에서는 이미지, 모델명, 핵심 상태만 요약된다.

키워드: `rounded card`, `accordion`, `collapsed summary`, `expanded detail`, `chevron`, `quantity stepper`, `change button`.

### P05. Product Grid / Product Detail

- 판매리스트는 2열 상품 그리드.
- 카드 내 이미지 영역은 연회색 배경, 바이크 이미지는 중앙 크게 배치.
- 배지: `프로모션`, `일시품절`.
- 가격 패턴: 정가 취소선 → 할인율 빨간색 → 실구매가 bold → 충전유형 chip.
- 제품상세는 히어로 이미지 carousel, 가격 비교, 보조금 확인 배너, 스펙/구성/리뷰/Q&A로 이어진다.

키워드: `two-column grid`, `bike image`, `promotion badge`, `sold out`, `strikethrough price`, `discount rate`, `final price`, `home charging`, `BSS`.

### P06. Filter / Select / Segmented Control

- 필터는 바텀시트로 열린다. 제조사, 가격대, 충전유형, 구동방식 등 조건 선택.
- 옵션선택은 label + select field + dropdown 리스트 구조.
- 충전유형은 `BSS형`과 `홈충전형` segmented control.
- 선택된 필드는 파란 outline 또는 연한 파란 배경으로 표시.
- dropdown 항목 우측에는 추가금액 또는 선택 상태가 붙는다.

키워드: `filter sheet`, `select field`, `dropdown`, `segmented control`, `BSS형`, `홈충전형`, `blue outline`, `selected option`.

### P07. Municipality Selection

- 보조금 신청은 주민등록상 주소 기준이므로 지자체 선택 화면이 별도 존재한다.
- 1단계: 시/도 리스트. 2단계: 시/군/구 리스트.
- 선택한 시/도는 chip으로 상단에 표시되고, 최종 선택된 시/군/구는 check로 표시된다.
- 잘못 선택하면 보조금 신청이 불가능할 수 있다는 안내가 함께 있다.

키워드: `municipality`, `registered address`, `province`, `city`, `district`, `selected chip`, `subsidy eligibility`.

### P08. Subsidy Selector / 추가보조금 선택

- 신청유형: 개인, 외국인, 개인사업자, 법인사업자.
- 추가지원 유형: 해당없음, 배달용, 장애인, 차상위 이하 계층, 농업인, 상이·독립유공자, 다자녀, 소상공인 등.
- 배달용은 `기존배달`, `신규배달`로 세분화된다.
- 선택 화면 하단에는 예상 실구매가 또는 예상 결제금액이 sticky로 노출된다.
- 선택 완료 후 주문금액 카드에 기본보조금/추가보조금이 할인 항목으로 반영된다.

키워드: `additional subsidy`, `applicant type`, `delivery rider`, `new delivery`, `existing delivery`, `priority support`, `expected final price`, `discount applied`.

### P09. Payment Method / Reservation Deposit / Remaining Balance

- 예약금은 `30,000원`으로 고정 표시.
- 결제수단은 카드와 가상계좌가 기본이며, 잔여금 결제에서는 분할결제까지 확장된다.
- 카드 결제: 결제중 화면 → 결제완료 화면.
- 가상계좌: 은행 선택, 입금자명, 현금영수증 신청, 준비완료, 계좌번호 복사.
- 잔여금 결제: 전체 금액 또는 2~3회 분할결제. numeric keypad와 금액 chip 사용.

키워드: `reservation deposit`, `30,000원`, `card payment`, `virtual account`, `bank selection`, `cash receipt`, `payment processing`, `payment complete`, `split payment`, `numeric keypad`.

### P10. Document Submission / Government24 / Kakao Wallet

- 서류작성은 전체 화면 중 가장 복잡한 영역이며, 정부 행정 절차를 앱 가이드로 분해한다.
- 신청유형별로 필요한 서류가 달라진다.
- 제출 방식은 크게 앱 내 파일 업로드, 정부24 제출, 카카오톡 전자증명서 제출로 나뉜다.
- 정부24/카카오톡 화면으로 이동하기 전에 앱에서 단계별 안내를 제공한다.
- 외부 앱/웹에서 완료 후 다시 바드림 앱으로 돌아와 제출 확인을 진행하는 패턴이 반복된다.

키워드: `document submission`, `Government24`, `Kakao wallet`, `electronic certificate`, `third-party submission`, `file upload`, `certificate guide`, `processing complete`, `recipient name`, `retry`.

### P11. E-signature / Review Waiting / Supplement Request

- 전자서명은 여러 문서를 순서대로 서명하는 구조.
- 다음 문서는 이전 문서 서명 완료 후 활성화된다.
- 공고 오픈 전 또는 서류 검토 중에는 대기 화면이 제공된다.
- 서류보완 필요 시 보완할 서류 리스트, 보완 사유, 파일 추가/제출완료 상태가 표시된다.

키워드: `e-signature`, `sequential signing`, `document preview`, `signature complete`, `document review`, `public notice waiting`, `supplement request`, `reupload`.

### P12. Order Status / Shipment / Detail Actions

- 주문현황은 사용자가 현재 위치를 잃지 않도록 상태 제목을 크게 제시한다.
- 보조금 신청 접수, 자격부여, 출고예정일 확정, 대상자선정, 잔여금 결제, 출고대기, 출고완료로 흐른다.
- 하단에는 `주문상세`, `신청서류 다운로드`, `보조금 신청현황`, `사용신고필증 주의사항` 등 보조 액션이 반복된다.
- 출고대기에서는 출고장, 대리점, 탁송, 2대 이상인 경우를 구분한다.

키워드: `order status`, `subsidy review`, `qualification`, `delivery date`, `remaining balance`, `shipment`, `delivery completed`, `document download`, `order detail`.

### P13. Alert / Bottom Sheet / Toast / Loading / Success

- Alert: 중앙 흰색 카드, dim overlay, 제목 + 설명 + 1~2개 버튼.
- Bottom Sheet: 하단에서 올라오는 sheet, 상단 radius, 내부 선택 리스트와 CTA.
- Toast: 짧은 완료/알림 메시지. `~되었어요` 톤.
- Loading: 중앙 spinner 또는 아이콘, `처리하고 있어요`, `잠시만 기다려주세요`.
- Success: 체크 아이콘, 완료 제목, 다음으로 이동하는 확인 CTA.

대표 문구: `인증이 정상적으로 처리되지 않았어요`, `주민등록초본 발급을 그만할까요?`, `제출한 서류를 삭제할까요?`, `예약금 결제가 완료되었어요`, `결제를 처리하고 있어요!`.

### P14. Review Writing

- 리뷰는 제품 리뷰와 서비스 리뷰로 분기된다.
- 제품 리뷰는 별점, 사진 첨부, 상세 내용 입력이 핵심.
- 서비스 리뷰는 만족도/경험 평가 성격.
- 사진 선택은 팝업 또는 바텀시트로 처리하고, 이탈 시 리뷰쓰기 취소 팝업을 노출한다.
- 최종 완료 화면은 간결한 성공 메시지 + 확인 CTA.

키워드: `review writing`, `product review`, `service review`, `star rating`, `photo upload`, `cancel popup`, `final complete`.

### 5.8 `7. 서류작성`

**역할**  
전기이륜차 보조금 신청에 필요한 신청자 정보와 증빙서류를 수집한다. 전체 화면 중 가장 크고 복잡한 섹션으로, 행정 절차를 모바일 단계형 가이드로 바꾼 영역이다.

**상위 구조**

```text
7. 서류작성
  ├─ 1. 기존 입력한 정보확인

  ├─ 3. 추가지원
  ├─ 4. 신청정보입력
  ├─ 5. 서류제출
  │   ├─ 1. 제출화면
  │   ├─ 2. 초본발급화면
  │   ├─ 3. 제출안내 (제3자제출)
  │   └─ 4. 제출안내 (나머지서류)
  ├─ 6. 주요안내
  ├─ 7. 제출완료
  └─ 나가기 팝업
```

**반복 구조**

- 전역 헤더: 닫기 X, 우측 문의, 얇은 progress bar.
- 기존 정보확인: 이전에 입력/선택한 신청정보를 보여주고 다시 선택 여부 확인.
- 신청유형: 개인, 개인사업자, 법인사업자, 외국인.
- 추가지원: 개인/외국인, 개인사업자, 법인사업자에 따라 서류와 유형이 달라진다.
- 신청정보입력: 이름, 연락처, 생년월일, 이메일, 주민등록상 주소, 배송 주소, 사업자/법인/외국인 정보.
- 주요안내: 보조금 취소/환수 가능성, 신청 조건, 사용자가 확인해야 할 안내.
- 서류제출: 유형별 필요서류 리스트와 제출 상태.
- 제출완료: 보조금 신청서류 제출 완료 후 주문현황 또는 전자서명 단계로 이동.

**주요 서류 유형**

`주민등록초본`, `사업자등록증명`, `국세납세증명서`, `지방세납세증명서`, `법인등기부등본`, `외국인등록사실증명`, `소상공인확인서`, `가족관계증명서`, `장애인증명서`, `국가유공자확인서`, `수급자증명서`, `농업인증빙서류`, `배달용증빙서류`, `탄소중립포인트(에너지)가입확인서`.

## 7. 화면 생성 또는 재구성 시 지켜야 할 규칙

### 7.1 UI 규칙

- 모바일 기준 좌우 여백을 넉넉히 둔다. 기본적으로 20px 내외 여백을 사용한 느낌.
- 카드 radius는 부드럽게, 입력/선택 필드는 12px 내외, bottom sheet와 popup은 더 큰 radius.
- Drop shadow는 과하게 쓰지 않는다. 카드 구분은 대부분 배경색, border, 여백으로 만든다.
- primary action은 반드시 하단 CTA로 명확히 제공한다.
- 복잡한 서류/보조금 화면은 한 화면에 모든 설명을 몰아넣기보다 단계별로 나눈다.

### 7.2 UX Writing 규칙

- 기본 어조는 해요체.
- 제목은 사용자가 지금 해야 할 행동을 직접 말한다.
- 행정/서류/보조금 관련 불안 요소는 겁주지 않고 정확히 설명한다.
- 완료 문구는 `~되었어요`로 짧고 분명하게 쓴다.
- 오류는 `실패`보다 `정상적으로 처리되지 않았어요`처럼 부드럽게 표현한다.
- 버튼은 `~하기`, `확인했어요`, `알림 받으면 돌아올게요`, `네, 최종 제출할게요`처럼 행동이 드러나야 한다.

### 7.3 정보 구조 규칙

- 보조금/금액은 반드시 breakdown으로 보여준다.
- 지자체, 신청유형, 추가지원 유형은 가격과 서류에 영향을 주므로 변경 가능한 정보로 노출한다.
- 현재 단계와 다음 단계가 항상 보여야 한다.
- 사용자가 중간 이탈 후 돌아와도 홈-내차고와 주문현황에서 바로 복귀할 수 있어야 한다.
- 서류 제출은 `필요서류 → 제출방법 → 외부 서비스 단계 → 제출확인 → 완료` 순서를 유지한다.

## 9. 한 문장 요약

이 화면 묶음은 **일반 커머스 앱의 상품 구매 플로우에 전기이륜차 보조금 행정 절차를 결합한 모바일 체크아웃 시스템**이다. 핵심은 사용자가 상품을 고르는 순간부터 보조금, 서류, 전자서명, 심사, 잔여금, 출고까지 길고 복잡한 절차를 잃어버리지 않도록 **현재 상태와 다음 행동을 카드, stepper, timeline, bottom CTA로 계속 안내하는 것**이다.
